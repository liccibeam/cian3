# Проморолик мобильной главной Циана

Сценарий подтверждён пользователем 23.11.2026. Первая версия ролика готова к просмотру; приёмка самого видео ещё не получена.

- 15,00 секунды, 1920 × 1080, 16:9, 30 fps, 450 кадров.
- MP4: H.264, yuv420p, BT.709; AAC, 48 кГц; лимит 20 000 000 байт проверяется сборкой.
- Русские промотитры; озвучки нет. Музыка — синтезированная черновая инструментальная подложка, без чужих сэмплов.
- Локальный файл после сборки: `out/home-promo_16x9.mp4` (4,75 МБ). MP4 в Git не хранится; пользователь загружает его на платформу отдельно.
- Кадры из итогового MP4: [out/home-promo_16x9_sheet.jpg](out/home-promo_16x9_sheet.jpg).

## Утверждённый сценарий

| Время | Экран / действие | Промотекст |
|---|---|---|
| 0–3 с | Мобильная главная возвращающегося пользователя; камера приближается к сохранённому поиску | Не начинайте поиск заново |
| 3–7 с | Нажатие на сохранённый поиск; выдача: Сокольники, 2 комнаты, до 20 млн ₽ | Ваш поиск — под рукой |
| 7–11 с | Прокрутка до единственной квартиры за 18,4 млн ₽; открытие карточки | Перейдите к выбору квартиры |
| 11–15 с | Карточка остаётся в кадре; финальный логотип и приглашение | Найдите своё место · Начните с главной |

Вспомогательные титры «Вернитесь к тому, что искали» и краткая запись условий — редакционные надписи вокруг интерфейса. Экраны и их подписи не перерисованы; поверх добавлены обрамление, подсветка и индикатор касания.

## Источники

Снимки — действующая локальная React-сборка репозитория, базовый коммит `689c20d`. Скрипт `capture.py` проходит путь реальными кликами в отдельном браузерном контексте. Старт: `/?scenario=returning`; сохранённые критерии переходят в URL выдачи; из результата открывается `/listing/1`. Личное хранилище браузера пользователя не используется.

Исходный размер — 390 × 844, плотность 2×. Файлы в `assets/`: полные страницы без фиксированного таббара, отдельно снятые настоящие таббары, снимки viewport; `capture.json` содержит URL, размеры элементов и SHA-256. Прокрутка в ролике вычисляется по времени поверх полных снимков, таббар остаётся на месте. Данные и фотографии — существующие демонстрационные материалы прототипа.

Логотип, Lato и цвета — из `motion/brand/`, снимок профиля — `brand/`. Лицензия Lato приложена. Исходное приложение и `public/reference/` не менялись.

## Пересборка в PowerShell из корня репозитория

Используются локальная `.venv`, ffmpeg и ffprobe в PATH. Зависимости: Python 3.9+, playwright, numpy, scipy, pillow; Chromium устанавливается командой `python -m playwright install chromium` в том же окружении. Для этого ролика `faster-whisper` не нужен.

```powershell
.\motion\home-promo\render.ps1
```

Скрипт проверяет сцену, создаёт контактный лист, синтезирует музыку, рендерит кадры, сводит звук, проверяет длительность, кодеки, декодирование и размер. Рендер полностью локальный и не требует работающего прототипа: проверенные снимки сохранены в `assets/`.

Чтобы обновить экраны после изменения продукта, сначала запустите сборку и превью:

```powershell
npm run build
npm run preview -- --port 5195 --strictPort
```

В другом терминале:

```powershell
.\.venv\Scripts\python.exe -X utf8 motion\home-promo\capture.py
.\motion\home-promo\render.ps1
```

Превью монтажа: запустите локальный HTTP-сервер из этой папки и откройте `video.html?preview=1`. План — `plan.js`, движение — `scene.js`, оформление — `film.css`. Движок и инструменты — установленный `product-motion`.

## Проверки и ограничения

`verify_scene.py`: Lato загружен, ошибок JavaScript нет, повторный рендер 12 временных точек в прямом и обратном порядке совпадает, финальные две секунды статичны. `verify_media.py`: 450 кадров, 15 секунд, разрешение и кодеки соответствуют брифу, декодирование без ошибок. Проверяются кадры уже закодированного MP4, а не только HTML.

Проверки исходного прототипа: typecheck, lint, build; 35 тестов проходят. Новых функций и интерфейсных изменений нет. Музыка не прослушивалась агентом; приёмка автором и публикация не выполнялись.

`build/` и MP4 исключены из Git. Снимки и исходники позволяют повторить сборку; для передачи вне рабочей папки MP4 нужно приложить отдельно.
